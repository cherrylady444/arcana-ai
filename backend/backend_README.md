# Arcana AI Backend

This folder contains the ASP.NET Core backend for the AI tarot reading application.

The backend is responsible for:

- exposing the main HTTP API;
- drawing tarot cards securely;
- owning the main PostgreSQL database schema;
- storing reading sessions and drawn cards;
- calling the Python AI service for interpretation;
- later handling authentication, reading history, saved readings, sharing, rate limits, and admin endpoints.

The intended architecture is:

```text
Tarot.Api
  Receives HTTP requests and returns HTTP responses.

Tarot.Application
  Contains use cases such as CreateReading, GetReadingHistory, SaveReading.

Tarot.Domain
  Contains core business objects such as TarotCard, ReadingSession, DrawnCard, Spread.

Tarot.Infrastructure
  Contains PostgreSQL, Entity Framework Core, Redis, and Python AI service integration.

Tarot.Tests
  Contains automated tests.
```

Dependency direction:

```text
        Tarot.Api
        /       \
       v         v
Application   Infrastructure
       \         /
        v       v
          Domain
```

## 3. Clean generated files before committing

The uploaded backend currently includes `obj/` folders. These are generated by .NET and should not be committed to GitHub.

From the `backend/` folder, run:

```bash
find . -type d \( -name "bin" -o -name "obj" \) -prune -exec rm -rf {} +
```

Then make sure your root `.gitignore` includes:

```gitignore
# .NET
bin/
obj/
*.user
*.suo
.vs/
TestResults/
coverage/
```

## 4. Restore dependencies

Run from the `backend/` folder:

```bash
cd backend
dotnet restore Tarot.slnx
```

This downloads all NuGet packages used by the backend projects.

## 5. Build the backend

Run from the `backend/` folder:

```bash
dotnet build Tarot.slnx
```

Expected result:

```text
Build succeeded.
```

If the build fails, fix the first error shown by the compiler before moving forward.

## 6. Run tests

Run from the `backend/` folder:

```bash
dotnet test Tarot.slnx
```

At the beginning, the test project only contains the default xUnit test. Later, this project should test card drawing, validation, API behavior, and database integration.

## 7. Run the API locally on the server

Run from the `backend/` folder:

```bash
dotnet run --project Tarot.Api
```

The current `launchSettings.json` configures the HTTP profile to use:

```text
http://localhost:5000
```

Test the API from another terminal:

```bash
curl http://localhost:5000/
curl http://localhost:5000/health
```

Expected response from `/`:

```json
{
  "service": "tarot-backend",
  "status": "ok"
}
```

The `/health` endpoint should return HTTP 200 if the backend is alive.

## 8. Run the API on a fixed development port

For Docker and frontend integration, it is useful to standardize the backend port.

Run:

```bash
ASPNETCORE_URLS=http://0.0.0.0:5000 dotnet run --project Tarot.Api --no-launch-profile
```

Then test:

```bash
curl http://localhost:5000/
curl http://localhost:5000/health
```

Use `0.0.0.0` when you want the server process to accept connections from outside the container or remote machine.

Use `localhost` when you only want access from the same machine.

First make sure the Dockerfile uses `Tarot.slnx`, not `Tarot.sln`.

Then run from the `backend/` folder:

```bash
docker build -t arcana-backend:dev .
```

Run the container:

```bash
docker run --rm -p 5000:8080 arcana-backend:dev
```

## 12. Recommended next backend implementations before frontend

Before starting the frontend, implement a small backend-only vertical slice.

Recommended order:

```text
1. Fix project cleanup
   - remove obj/bin folders from Git
   - rename Tarot.Domain/TarotCard to Tarot.Domain/TarotCard.cs
   - fix Dockerfile to use Tarot.slnx

2. Add domain models
   - TarotCard
   - CardOrientation
   - SpreadPosition
   - DrawnCard
   - ReadingSession

3. Add secure card drawing service
   - use RandomNumberGenerator, not Random
   - draw unique cards
   - assign upright/reversed orientation
   - assign spread positions

4. Add unit tests for card drawing
   - returns exactly 3 cards for 3-card spread
   - does not duplicate cards
   - only uses valid orientations

5. Add fake POST /api/readings endpoint
   - receives a user question
   - draws 3 cards
   - returns JSON response
   - does not use PostgreSQL yet
   - does not call Python AI service yet

6. Add PostgreSQL later
   - DbContext
   - EF Core migrations
   - seed tarot cards
   - store reading sessions

7. Add Python AI service call later
   - backend sends already-drawn cards
   - AI service returns structured interpretation
```

Only after `POST /api/readings` works from `curl` should the frontend form be started.

## 15. Development principle

Do not start with authentication, frontend design, RAG, LangGraph, or deployment.

Start with this:

```text
Can the backend receive a question and return 3 securely drawn tarot cards?
```

Once that works, add database persistence.

Once database persistence works, call the Python AI service.

Once backend + AI service works, build the frontend.
